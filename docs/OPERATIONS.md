## 1. 产品总览

**邻里鲜选 AI 运营台** 是一个面向即时零售场景的 Agentic RAG 平台，覆盖三个业务闭环：

| 闭环 | 链路 | 使用角色 |
|---|---|---|
| **客服质检闭环** | 顾客问题 → AI 生成回复建议 → 人工审核采纳/修订 → 风险升级主管 → 主管决策 → 质检与知识缺口回填 | 客服、主管 |
| **即时零售运营闭环** | 购物篮数据 → 关联规则 → 运营方案（草稿→确认→发布）→ 执行任务 → 复测验证 → 结果回填 | 运营、管理员 |
| **知识管理闭环** | 知识库文档 → 解析分块 → 版本发布 → 检索引用 → 评测与发布决策 | 管理员 |

界面按"浅色业务 + AI 辨识"设计：业务事实区域为白色/浅灰，AI 判断区域使用**极浅靛蓝背景 + AI 徽标**标识；仅 Trace 链路等**技术执行细节**使用深色面板。

## 4. 客服工作台

**入口**：左侧导航「客服工作台」（默认首页）。

界面为三栏：

```
┌──────────────┬──────────────────┬──────────────────┐
│ 工单队列      │ 客户会话          │ AI 回复建议       │
│ （列表/筛选） │ （对话主角）       │ （浅靛蓝 AI 面板） │
└──────────────┴──────────────────┴──────────────────┘
```

### 4.1 左栏：工单队列

- 顶部统计 4 项指标：**待处理 / 解决率 / AI 采纳率 / 引用覆盖**
- 状态筛选：待处理 / 处理中 / 已升级 / 全部
- 搜索：按顾客、主题或工单号过滤
- 每行显示：主题、顾客、最后消息、优先级、状态、工单号；**点击选中**（浅靛蓝高亮 + 左侧指示条）

### 4.2 中栏：客户会话（视觉主角）

- 顶部：工单标题、渠道、工单号；操作按钮 **接单**、**解决**
- 案例数据溯源区：展示该工单数据来源（真实观测字段 vs 合成字段），避免把演示数据包装成真实
- 消息流：客户消息（左）/ 客服消息（右）
- 底部输入框：**人工回复**——不依赖 AI 也能完成处理

### 4.3 右栏：AI 回复建议（浅靛蓝 AI 面板）

| 区块 | 说明 |
|---|---|
| 订单上下文 | 当前工单关联的订单、履约、退款事实（交易事实，不属于 AI 判断） |
| AI 回复建议 | 「生成」按钮调用模型 + 已发布知识生成对客回复草稿 |
| 当前判断 | 风险等级、缺失事实、建议动作（AI 审核摘要） |
| 引用证据 | 每条建议附引用来源，可展开核对 |
| 回复草稿 | 可编辑文本区（**人工审核后**再发送） |

**完整处理流程：**

```
1. 选中工单 → 查看客户会话与订单上下文
2. 点击「生成」→ AI 输出建议草稿（含引用证据与风险提示）
3. 人工审核：
   ├─ 原样采纳      → 点「采纳并发送」
   ├─ 修订后再发    → 修改草稿 → 点「发送修订版」
   └─ 高风险/证据不足 → 点「升级主管」（自动附带 AI 诊断信息）
4. 处理完成 → 点「解决」并记录解决码与备注
```

> ⚠️ AI 建议仅作辅助，**发送前必须人工确认**；检测到退款/支付/食品安全风险时会红色警示。

## 5. 主管队列

**入口**：左侧导航「主管队列」（主管/管理员可见）。

### 5.1 队列列表（左栏）

- 页头统计：待处理升级 / 已接管 / 高风险 / 已解决
- 筛选：全部 / 待处理 / 已解决 / 已退回
- 每行：案件主题、顾客、分类、**SLA（升级时长）**、风险等级、状态；**高风险行带红色左侧指示条**
- 点击行 → 右侧详情面板

### 5.2 详情面板（右栏）

- 案件概要：主题、顾客、工单号、升级时间、风险等级 + 分类
- **升级原因**（客服提交）
- **AI 风险诊断**（浅靛蓝面板 + AI 徽标）：intent / risk / terminal / 缺失事实
- 处理备注输入框

### 5.3 决策按钮层级

| 权重 | 按钮 | 说明 |
|---|---|---|
| 主要 | **批准退款**（靛蓝实心） | 决议：approved_refund |
| 次要 | 批准补偿 / 要求补充材料 / 转专员 / 接管 | 线框按钮 |
| 弱化 | 退回客服 | Ghost |

决议记录后同步回工单（状态机：pending → accepted → resolved / returned / transferred）。

## 6. 质量与缺口

**入口**：客服运营分组 →「质量与缺口」（主管/管理员）。

- 指标卡：已复核 / 质检通过 / 待修缺口
- **知识缺口队列**：质检中发现的规则缺口（如"退货规则未覆盖鲜活商品"）→ 状态流转、按严重度排序
- **知识发布**：版本历史（冻结文档 + 哈希不可变）、发布规则、激活生效版本；**正式回复只检索当前生效版本**
- **上线前评测**：选择候选版本 → 运行固定用例评测 → 得分与运行状态
- **客服运营报告**：人工复核量、质检通过率、知识健康度、案例覆盖（真实/演示分开统计）、数据口径说明

## 7. 知识发布与知识库管理

### 7.1 知识发布（管理员）

1. 在知识库管理上传文档（txt / markdown / 表格等）→ 自动解析分块
2. 创建**发布版本**（冻结文档快照 + 内容哈希）
3. 发布后：成员关系与哈希**不可变**；可随时**切换生效版本**
4. 切换版本不删除历史版本（可回滚）

### 7.2 知识库管理（管理员）

- 知识库列表 → 文档管理 → 分块管理（逐块查看/修正）
- 顶部搜索框（Ctrl K）全局搜索知识库与文档
- 文档状态：上传（202 异步受理）→ 解析 → indexed（可检索）

## 8. 商品组合洞察与运营方案

**入口**：左侧导航「商品组合洞察」（运营/管理员）。

### 8.1 关联规则发现

购物篮数据导入后自动计算**关联规则**（Apriori 风格）：规则展示 Lift / Confidence / Support / 基于 N 个购物篮 / 证据来源。

```
牛肉 → 根茎类蔬菜
Lift 2.41 · Confidence 68% · Support 13% · 基于 1,282 个购物篮
```

### 8.2 运营方案状态机

```
草稿 draft → 已确认 confirmed → 已发布 published
                          ↘ 已拒绝 rejected
```

| 动作 | 权限 | 说明 |
|---|---|---|
| 创建方案 | operator/admin | 绑定一条规则；同规则已有未完成方案时拒绝（防重复） |
| 确认方案 | operator/admin | 确认后生成版本 v1 |
| 发布方案 | **仅 admin** | 发布到 AI 客服，进入任务执行阶段 |
| 拒绝方案 | operator/admin | 记录拒绝原因 |

### 8.3 优化任务闭环

1. 方案发布后自动生成**优化任务**（assign/verify/advance 状态机）
2. 运营指派执行人 → 执行 → **复测**（对同一规则重新评估，评价指标变化）
3. 验证结果**回填**到方案（completed），形成"发现机会 → 创建 → 确认 → 发布 → 执行 → 验证"闭环

### 8.4 数据来源与同步

- 页面标注数据来源（observed 真实 / synthetic 合成），顶部有**同步**按钮与失败回填任务
- 数据导出：生成运营周报 / 导出运营洞察报告

## 9. 用户管理

**入口**：设置 →「用户管理」（admin 与 operator 可见）。

- 用户表格：用户名 / 角色（客服、客服主管、商家运营、管理员）/ 组织 / 状态 / 操作
- 操作：启用/停用、修改角色
- 角色 badge 克制配色：客服（neutral）、客服主管（indigo soft）、运营（blue soft）、管理员（dark）

## 10. 系统设置

**入口**：设置 →「系统设置」（admin）。

- 分节表单（section + divider，非大卡片）：模型配置（模型 / Temperature / Timeout）、检索设置（Top K / Threshold）等
- **保存更改**带版本号 CAS 校验（expectedVersion 不匹配时拒绝，防并发覆盖）
- 修改记录写入**审计日志**（RuntimeSettingAudit）

## 11. 链路追踪

**入口**：左侧导航「链路追踪」（admin）。

- 运行列表：Run 状态（成功/失败/运行中）、耗时、评估
- **Trace 详情**：节点树 + 每步的工具、耗时、状态；**技术细节（JSON 负载等）使用深色面板**——这是全站唯一允许大面积深色的区域（技术执行细节语义）
- 高级诊断能力：Step / Tool / Duration / Status / Evidence / Error / Evaluation / Release Decision

## 12. 常见问题

| 现象 | 原因与处理 |
|---|---|
| 登录提示"用户名或密码错误" | 确认账号密码；演示环境统一为 `AdminDemo@2026` |
| 某菜单看不到 | 权限不足（菜单按角色+权限过滤）；换对应角色账号登录 |
| 访问某页面提示 403 | 后端 API 权限硬校验拦截，属预期行为 |
| 点「AI 生成」报"网络错误" | 模型服务未配置（.env 缺模型 key）或后端未启用向量检索；可先用人工回复 |
| 点「生成」提示"建议暂不可用" | 已发布知识不足（insufficient_evidence）→ 补充规则或升级主管 |
| 创建运营方案提示"该关联规则已有未完成的运营方案" | 防重复校验：先处理（确认/发布/拒绝）已有方案 |
| 工单数据为空 | 当前账号未绑定组织成员关系；管理员在演示环境重新 seed 或绑定成员 |
| Trace 详情 JSON 是深色面板 | 设计如此：深色仅用于技术执行细节 |
