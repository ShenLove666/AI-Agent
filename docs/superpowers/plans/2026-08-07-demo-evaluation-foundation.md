# Demo and Evaluation Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the migration, reproducible demo-data, public-source metadata, minimal evaluation-dataset, API-contract, and unified verification foundations required by the merchant AI operations demo.

**Architecture:** Keep the FastAPI modular monolith and SQLite default. Introduce Alembic as the only forward schema mechanism, identify demo ownership at the user boundary, store public-source provenance on documents, and add evaluation datasets/cases without yet implementing evaluation runs or dashboards. Seed data through an idempotent domain service used by the CLI, and verify active frontend service calls against FastAPI OpenAPI.

**Tech Stack:** Python 3.12, FastAPI, SQLAlchemy 2, Alembic 1.x, Pydantic 2, SQLite, pytest, React 18, TypeScript 5, Vite 5, PowerShell.

## Global Constraints

- Modify only `D:\Project\rag-project`; treat `D:\Project\ragent-main` as read-only reference material.
- Default runtime remains SQLite plus local files; Redis, Milvus, and an LLM API are not prerequisites for seeding or browsing demo data.
- Demo records must be visibly and structurally distinguishable from user-created data.
- Public material is stored as a concise original summary plus source URL, publisher, retrieval date, and usage note; do not copy whole copyrighted platform-rule pages.
- Do not add Agent, MCP, knowledge-graph, intent-tree, evaluation-run, or dashboard-redesign scope to this change.
- Never read, log, commit, or copy API keys; `.env`, `data/`, `.venv/`, `node_modules/`, and generated build output stay ignored.
- Every schema change after the baseline has an Alembic upgrade and downgrade.
- Use test-first development: observe the focused test fail before implementing each behavior.
- The working directory currently has no Git repository. Task 1 establishes a safe local baseline before later commit steps.

```python
def upgrade_database(database: Database) -> None:
    config = build_alembic_config(database.engine.url.render_as_string(hide_password=False))
    tables = set(inspect(database.engine).get_table_names())
    if "alembic_version" not in tables and tables:
        adopt_pre_alembic_schema(database)
        command.stamp(config, "0001_current_schema")
    command.upgrade(config, "head")
```
