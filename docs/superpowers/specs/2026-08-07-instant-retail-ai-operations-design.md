# 即时零售商超 AI 运营闭环设计

日期：2026-08-07  
状态：用户已确认产品方向

## 1. 产品定位

项目从通用 RAG/数码售后演示升级为“即时零售商超 AI 运营平台”，服务一个虚构但业务口径一致的社区商超。平台用真实购物篮记录发现经营机会，再通过 AI 客服、知识库、评测标注和优化任务验证落地效果。

该定位直接对应目标 JD 的四项职责：商家 AI 产品落地、Agent 质量优化、数据洞察与运营分析、行业研究与成果输出。

## 2. 可演示的业务闭环

```text
商家接入与目标配置
  → 购物篮数据质量检查与关联分析
  → 生成可解释的搭配购/活动建议
  → 将活动规则和服务 SOP 发布到 AI 客服知识库
  → 用标准问题集执行评测并进行人工标注
  → 聚合失败原因、知识缺口和使用效果
  → 创建优化任务、更新版本并重新评测
  → 输出运营周报和优化前后对比
```

主演示案例为“提升即时零售连带购并降低活动咨询转人工率”。用户能够从“牛肉与根茎类蔬菜”等关联关系下钻到订单证据，创建运营方案，再验证客服能否正确解释活动和推荐组合。

## 3. 数据策略

### 3.1 真实来源数据

读取用户授权的数据目录中的：

- `GoodsOrder.csv`：43,367 条购物篮明细、9,835 个购物篮、169 种商品；
- `GoodsTypes.csv`：商品到品类的映射，明细匹配率约 99.8%。

原始数据只提供订单号与商品名，不包含时间、金额、用户、门店、渠道或履约信息。系统不得将这些缺失字段描述为真实来源字段。

### 3.2 补充演示数据

为完整演示商家运营，使用固定随机种子生成订单时间、门店、渠道、商品价格、履约、售后、活动曝光和客服使用事件。所有补充记录必须携带 `data_origin=synthetic`；原始购物篮记录标记为 `data_origin=source`。界面、导出报告和 README 必须解释这一边界。

仓库只保存运行所需的精简、脱敏派生样例及来源说明。由于原目录未发现明确许可证，不公开打包完整原始文件；本地导入命令接受用户提供的源目录。

### 3.3 可复现性

- 导入和生成命令可重复执行且不产生重复记录；
- 同一随机种子产生相同演示数据和统计结果；
- 清理演示数据不得删除普通用户或其文件；
- 指标均从数据库聚合，不提供随机兜底值。

## 4. 一期功能范围

### 4.1 商家接入

商家档案包含业态、门店数、经营目标和当前阶段。接入清单展示数据导入、知识库、评测集、模型配置和上线阈值的完成状态，并明确阻塞原因。

### 4.2 商品与购物篮洞察

- 数据概览：订单数、商品数、平均篮子大小、品类覆盖和数据来源；
- 关联规则：支持度、置信度、提升度及订单样本证据；
- 商品/品类筛选和规则排序；
- 运营建议只能引用计算所得规则，不能让模型虚构指标。

### 4.3 AI 运营方案

运营人员可从关联规则创建“搭配购”方案，记录目标商品、搭配商品、活动文案、适用渠道、状态和创建依据。系统提供基于规则证据的 AI 文案草稿，但最终发布由运营人员确认。

已发布方案转换为结构化活动规则与知识文档，供客服检索。历史版本必须保留，评测运行引用具体方案和知识版本。

### 4.4 Agent 评测与标注

- 评测案例覆盖推荐准确性、活动口径、配送、退款、缺货替代和越权拒答；
- 运行结果记录关键点覆盖、引用正确性、忠实度、拒答正确性和耗时；
- 人工标注支持通过/失败、失败类型、严重度和备注；
- 评测运行保存模型、Prompt、知识库和活动方案版本快照；
- 无模型 API 时仍可浏览种子评测结果，实时运行明确提示配置要求。

### 4.5 运营洞察与优化任务

驾驶舱展示接入漏斗、客服使用量、知识命中率、解决率、转人工率、反馈率、好评率和评测通过率。每个指标可下钻到真实事件、回答、引用或评测结果。

失败评测、负反馈、知识未命中和高频转人工问题可创建优化任务。任务状态为 `new → confirmed → optimizing → pending_verification → resolved`，包含负责人、证据、目标指标、变更版本和复测结果。

### 4.6 成果输出

系统生成可下载的运营周报，包含数据来源、核心洞察、问题清单、已采取动作、评测前后变化和下一步计划。报告不得声称未被系统数据支持的业务增长。

## 5. 信息架构

```text
运营总览
商家接入
购物篮洞察
AI 运营方案
AI 客服
知识运营
评测与标注
优化任务
运营报告
```

普通商家只能访问自己的数据；管理员可切换商家并查看系统配置。暂未接通真实 API 的页面不得暴露入口，也不得使用静态数字伪装成功状态。

## 6. 技术边界

- 后端保持 FastAPI、SQLAlchemy、Alembic 和 SQLite 的模块化单体；
- 前端保持 React、TypeScript、Zustand 和 Vite；
- 本地演示默认不依赖 Redis、Milvus 或外部任务队列；
- 内存向量库重启后必须通过受管启动重建演示索引，避免“种子成功但服务无向量”；
- 新表和字段通过 Alembic 迁移，不直接修改已有数据库；
- 所有写接口校验商家所有权，导出报告不包含敏感身份信息。

建议新增独立边界：`commerce` 管理商品、购物篮和活动；`operations` 聚合使用事件与指标；`optimization` 管理问题和复测。现有 `evaluation`、`knowledge`、`rag` 模块通过服务接口协作，不相互读取内部表实现。

## 7. 错误与降级

- 源文件缺列、乱码无法修复、商品映射异常或空数据时导入失败并给出行级摘要；
- 关联规则低于最小样本阈值时不生成建议；
- LLM 不可用时保留确定性洞察、历史评测和手工方案编辑；
- 指标分母为零时显示“暂无足够数据”，不显示 0% 误导用户；
- 报告生成失败不影响已经保存的洞察、任务和评测结果；
- 任何重试均保持幂等，不重复创建订单、事件或优化任务。

## 8. 测试与验收

### 后端

- 真实源文件编码修复、缺列拒绝、幂等导入和来源标记；
- 关联规则的支持度、置信度、提升度及最小样本阈值；
- 商家权限隔离、活动版本、评测快照和优化状态机；
- 指标聚合与证据下钻一致；
- Alembic 空库升级、现有库升级和降级。

### 前端

- 商家接入清单及阻塞状态；
- 购物篮规则筛选、证据下钻和方案创建；
- 评测标注、失败筛选、优化任务和前后对比；
- loading、empty、error、no-permission 和 demo/source 标签；
- 移动端导航、键盘操作和主要页面可访问性。

### 完成标准

- 一条种子命令建立可重复的商超演示环境；
- 用户可在 8 分钟内完成“洞察—方案—客服—评测—优化—报告”演示；
- 所有展示指标可追溯到数据库证据；
- 真实来源和模拟补充数据始终可区分；
- 后端测试、API 契约、前端测试、Lint 和 production build 全部通过；
- README 提供最短启动命令、演示账号、数据说明和面试演示脚本。

## 9. 分期

一期只实现上述可演示闭环，并优先交付“真实数据导入 + 购物篮洞察 + 运营总览”的首个可见版本。二期再增加带来源的电商 AI 竞品研究库、趋势简报和更完整的多商家实验，不阻塞一期求职展示。
