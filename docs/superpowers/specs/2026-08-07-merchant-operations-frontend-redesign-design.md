# 云桥数码 AI 运营台前端改版设计

## 目标

将当前通用 RAG 聊天界面改造成面向数码家电商家的 AI 运营产品。改版同时处理核心状态缺陷、页面层级、响应式体验和前端测试缺口，保留现有后端 API 与业务数据模型。

成功标准：用户能够稳定完成登录、选择知识范围、发起和取消流式问答、切换历史会话、查看引用；管理员能够快速理解知识库健康度和运营问题；常用页面不再呈现通用 AI 模板感。

## 信息架构

普通商家登录后进入对话工作台，管理员进入商家运营总览并可切换到对话。主导航收敛为：

- 运营总览：解决率、转人工率、知识命中率、负反馈和问题趋势。
- AI 客服：售后场景对话、知识范围、流式状态和引用证据。
- 知识运营：知识库、文档来源、索引状态和更新时间。
- 效果诊断：高频问题、负反馈、知识缺口和 RAG 运行轨迹。
- 系统管理：用户、模型、向量和运行配置。

不为尚未存在的商品、订单、物流后端实体制作假页面；这些页面在后续业务数据闭环变更中加入。

## 视觉系统

产品名称统一为“云桥数码 AI 运营台”。视觉以深海蓝 `#0B1220`、科技青 `#14B8A6` 和告警橙 `#F59E0B` 为核心，使用中性灰承载大面积内容。取消大面积装饰性渐变、玻璃拟态和无意义留白。

通过 CSS 变量定义颜色、间距、圆角、阴影、状态和排版 token。桌面端使用紧凑的运营工具布局；移动端使用抽屉导航、单列内容和全宽引用面板。状态颜色始终同时配合文字或图标，不只依赖颜色表达。

## 核心页面

### 登录

登录页提供产品价值说明、演示账号快捷填充和明确的加载/失败状态。认证初始化完成前显示启动屏障，避免本地 token 尚未校验时发生错误跳转。

### AI 客服

欢迎内容使用数码售后问题，而非“内容总结、任务拆解”等通用提示。顶部显示当前模型、向量检索状态和知识范围；消息区明确展示检索、思考、生成、取消、断流与重试状态；引用面板突出文档标题、命中片段和来源。

新会话只在用户首次发送消息时持久化。路由切换、历史消息加载和当前会话使用请求身份校验，过期响应不能覆盖用户后来选择的会话。

### 运营总览与知识运营

运营总览采用清晰的 KPI、趋势、问题分布和待处理事项层级。没有数据时说明需要什么数据以及如何生成，不使用看似真实的随机指标。知识运营统一文档状态、来源、更新时间和索引状态表达，并提供可操作的失败原因。

## 状态与错误处理

- 认证 store 增加显式 `initializing` 状态，路由守卫等待校验结束。
- SSE 将未授权、网络断开、服务端拒绝、用户取消和正常完成映射为不同状态。
- 会话加载使用请求序号或 AbortController 防止竞态。
- 所有主要页面提供 loading、empty、error 和 retry 状态。
- Toast 只用于短暂结果反馈；需要用户处理的错误留在页面内。

## 前端架构与性能

保持 React、Zustand、Vite 和现有服务层。路由使用 `React.lazy` 按页面拆包，PDF、Excel、Word、图谱和代码高亮继续按能力加载。拆分巨型页面为页面容器、查询 hook、领域组件和展示组件；全局 CSS 仅保留 token、reset 与通用布局，页面样式靠组合类和局部组件承担。

本次不更换组件库，不引入第二套全局状态管理，也不要求日常启动执行生产 build。

## 测试与验收

补充 jsdom 与 React Testing Library，测试真实用户可见行为：

- 认证初始化、成功登录、失败登录和权限路由。
- 演示账号填充和登录按钮状态。
- 新会话首次发送、历史会话快速切换和过期响应隔离。
- SSE 正常完成、401、断流、取消和重试。
- 欢迎页、空状态、错误状态、引用面板和移动侧栏。
- 管理路由懒加载及关键页面可访问性。

验收命令包括 Vitest、ESLint、API 契约检查和 Vite production build。构建应保持重型预览能力独立分包，常规入口不静态加载这些实现。

## 实施边界

本阶段优先完成登录、主布局、聊天主链路和运营总览，再处理知识运营页面的一致性。保留所有现有 API URL 与字段兼容；若测试发现后端契约真实缺失，单独记录，不在前端用假数据掩盖。
