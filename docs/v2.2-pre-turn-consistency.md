# v2.2 ConversationTurn 前置一致性

本轮先修复会直接污染 Turn、版本回答和重新生成的数据问题，再进入 Conversation State Engine。

## 历史状态恢复

- 会话列表优先使用后端 `lastTime`，重命名只更新标题，不改变最近聊天顺序；
- 历史消息将 `NORMAL / INTERRUPTED / ERROR / REJECTED` 映射为对应 UI 状态；
- “已停止生成”“生成失败”“请求被拒绝”由 `messageStatus` 渲染，不再修改回答正文。

## RequestRun 状态机

```text
processing -> completed
           -> failed
           -> cancelled
```

只有 `completed + Assistant.NORMAL` 可以回放缓存。取消后的部分回答会保留用于诊断，但相同 requestId 再次提交时会重新生成。

## 幂等指纹

`chat_request_runs.request_fingerprint` 是以下规范化字段的 SHA-256：

- conversation ID；
- question；
- deep thinking；
- RAG enabled；
- 排序去重后的 knowledge base IDs。

相同 requestId、不同指纹返回 `409 IDEMPOTENCY_CONFLICT`，不会复用旧 User Message 或旧答案。

## Prompt 上下文

ConversationTurn 上线前，Prompt History 只接纳 `message_status=NORMAL` 的 Assistant Message。ERROR、INTERRUPTED、REJECTED 的部分回答仍保留在数据库和历史界面，但不会影响后续模型生成。

## POST Streaming

兼容流式接口改为：

```http
POST /api/v1/rag/v3/chat
Content-Type: application/json
Accept: text/event-stream
```

问题、会话和知识库范围都位于 JSON 请求体，不进入浏览器历史、代理访问 URL 或 URL 长度限制。`knowledgeBaseIds` 使用严格正整数数组；非法、重复或混合字符串参数返回 422，不会退化为检索全部知识库。
